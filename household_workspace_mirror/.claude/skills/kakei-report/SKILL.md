# kakei-report — 家計・資産分析レポート生成

田中家の資産管理台帳と各社照会資料から、A4・7ページの分析レポートPDFを生成・更新する。
スクリプトは `create_report.py`（Python + reportlab・メイリオ）。

レポート構成（**7ページ・この順序と枚数を固定**）：
- **P1 ダッシュボード**：KPI（総資産／総負債／純資産）・金融資産内訳（円グラフ）・バランスシート・不動産×ローン明細・総合評価・前月からの資産の変化（発散バー）
- **P2 投資の見える化**：NISA生涯枠の進捗（夫婦）・企業型DCの積み上げ（年7%・複利）
- **P3 投資の見える化②（高配当株の恩株）**：配当だけで取得元本を何%取り戻したか。KPI（取得額／生涯配当／恩株達成度／年間配当ペース）・銘柄別ランキング上位12（取得単価×株数=取得額／配当累計を併記）・年別受取配当の推移・口座別サマリー・ハイライト。定数は `ONK_*`。**日本株（夫婦合算）＋SPYD**が対象。
- **P4 不動産投資と老後の設計**：ローン状況（住宅＋投資用2戸）・サブリース・老後収入の柱・夫婦の私的年金
- **P5 分析サマリー：強み・弱点・アクション**：強み／弱点リスク表／アクション／金融資産の歩み／定期資料チェックリスト
- **P6 保険・保障の総点検**：世帯の保障マップ・加入保険一覧・名義変更スキーム注記・保険の弱点・総括。**P6は数値非連動の保障分析ページ**（医療保険2本は掛け捨て・法人負担でP1〜P5の資産・負債・純資産に影響しない）。定数は `MED_*`
- **P7 世帯年収（実収入）の推移**：旅費_世帯年収まとめ.xlsx を参照し年次推移を自動表示（xlsxが無ければ注記へ退避しレポートは継続）

## 最重要：恩株ページ（P3）は恒久。再生成時も必ず含める

**P3「高配当株の恩株」は正式ページ。再生成・改修のときに絶対に落とさない。** 過去、別PCでの改修時にP3が抜け落ち、「恩株版が他のPCから見られない」分岐が起きた。ページを削る・並べ替える依頼が無い限り、P3は常に残す。P3以外に恩株ページを新設しない（重複させない）。

恩株の数値は冒頭の **`ONK_` 定数ブロック**（`# ==== 恩株データ` の直後）に集約。SBIの最新値が出たらここだけ差し替える。

| 定数 | 意味 |
|---|---|
| `ONK_COST` | 取得額(簿価)・夫婦日本株＋SPYD＝恩株の分母 |
| `ONK_DIV` | 生涯 受取配当(税引後・保有銘柄)＝分子 |
| `ONK_TTM` | 年間配当ペース（直近1年・税引後） |
| `ONK_LIFE_TOTAL` | 受取配当 生涯累計（国内＋米国・売却分含む） |
| `ONK_BY_YEAR` | 年別 受取配当（税引後）の推移グラフ |
| `ONK_RANK` | 銘柄別ランキング：(銘柄, 所有者, 口座, 取得単価, 株数, 取得額, 配当累計, 恩株%) |
| `ONK_ACCT` | 口座別サマリー：(口座, 取得額, 恩株%, 直近1年配当) |
| `ONK_NEAR` / `ONK_REM_Y` / `ONK_MORE` | ハイライト文・残り年数・その他銘柄の注記 |

`ONK_PCT`（恩株達成度）は `ONK_DIV ÷ ONK_COST` で自動計算。対象は日本株（夫婦合算）＋SPYD（米国高配当ETF）。SPCX・ボーイングは無配の成長株なので恩株に含めない。

## 最重要：数値は「3か所」に分散している

このスクリプトの一番の落とし穴。台帳が更新されたら **すべて必ず直す**こと。片方だけだとPDF内で数字が食い違う。

1. **named定数（冒頭の定数ブロック）** … 計算とグラフ描画に使う。
   P2のNISA進捗バー・DC積み上げ棒、P4のローン表が参照する。
2. **手書きの表示文字列** … ソース中に直接書かれた日本語の数字。**定数から計算していない**。
   - P1：KPIカード（`kpis`）／円グラフの内訳（`fin` のラベルと金額）／BSの「1億1,080万」等／不動産×ローン明細表（`rows`）／総合評価文（`summary`）／指標チップ（`chips`）
   - P5：強み（`strengths`）／弱点リスク表（`weaknesses`）／アクション（`actions`）／歩みの注記
   - P6：保障マップ（`maprows`）／加入保険一覧（`inslist`）／名義変更ボックス文／保険の弱点（`insweak`）／アクション（`insact`）／総括（`summ5`）。**ここは資産の数値とは連動しない**ので、台帳更新では基本いじらず、保険資料が届いたときだけ直す
3. **恩株の `ONK_` 定数ブロック（P3）** … 上記の表のとおり。SBIの保有証券一覧・配当履歴が更新されたら差し替える。P3のKPI・ランキング・グラフ・ハイライトはこの定数から描画。

つまり「定数 `HOME_LOAN` を直したのにKPIの総負債が変わらない」のは仕様。**KPI・表・本文の数字と、それを言葉で説明している箇所まで人手で追う**。

## 最重要：毎回同じレイアウトで出すための鉄則

このレポートは**座標・サイズ・行数を現在の文量に合わせて手調整した固定テンプレート**。だから原則は「**数値だけ更新し、レイアウト構造（座標・フォントサイズ・配色・行数・ボックス高さ）は触らない**」。レイアウトを動かすと毎回見た目が変わる。崩れるのは決まって**文量が増えたとき**なので、次を守る。

**構造は固定（行を安易に増減させない）**
- ページ数は必ず **7ページちょうど**（P3＝恩株、P7＝世帯年収を含む）。ページを足す・削る・並べ替える依頼が無い限り7ページを維持。
- 行数前提の要素：KPI 3枚／不動産×ローン表 3物件＋合計／P4ローン表 3本＋合計／老後の柱 5本／強み 5項目／チェックリスト 10件／P6保障マップ 6行・保険一覧 5行・弱点 5項目・アクション 4項目／P3恩株ランキング 上位12銘柄。増減したらレイアウト全体の再設計になるので、安易に足さない。
- **P5は縦が満杯**（最下コンテンツがページ下端まで約13ptしか余白がない）。P5に行を足す・折り返しを増やすと枠外へあふれる。P5へ足すなら同量どこかを削る。
- **P6は数値非連動の保障ページ**。医療保険2本（メットライフ・亨/美香）は掛け捨て・法人負担のため、台帳更新でP1〜P5の金額が動いてもP6の保障マップ・保険一覧は基本そのまま。保険の数値（`MED_*`）は資料が届いたときだけ直す（特に亨は暫定値）。

**1行ものの手書き文字列は枠内に収める**
- `strengths`（強み）・`actions`・KPI説明・各注記は**折り返さず1行で描く**実装。長くすると枠の右へはみ出す。
- 数値更新で文が伸びたら、**言い回しを縮めて1行に収める**（座標やフォントは変えない）。他ページと重複する数字を削るのが手っ取り早い。
- `wrap()` を使う箇所（`summary`・`weaknesses` の説明）は自動折り返しだが**ボックス高さは固定**。行数が増えると箱からあふれるので文量はほぼ現状維持にする。

**毎回必ず検証する（機械チェック＋目視）— これが「同じレイアウト」の担保**
生成したら付属ツール `verify_report.py` を必ず実行する。**期待ページ数は 7**。
```
python ".claude\skills\kakei-report\verify_report.py" "資産管理台帳_分析レポート_YYYYMMDD_vN.pdf" 7
```
- 第2引数に **期待ページ数 7** を必ず渡す（省略すると既定でページ数不一致の誤検知になる）。
- `LAYOUT OK` … ページ数7・マージン越えなし・下端あふれなし＝合格。
- `LAYOUT ISSUES` … はみ出した文字列が一覧表示される。**座標は動かさず、その文を縮める／重複を削る**で対処し、再生成→再検証。
- 同時に各ページPNG（`<PDF名>_p1.png`〜`_p7.png`）を書き出す。Read tool で7枚を開き、重なり・はみ出し・余白の偏りを目視する（poppler未導入のためPDF直レンダリングは不可。PNGで見る）。
- レビュー後、PNGは中間ファイルなので削除する。

## 作業フロー

### 0. 何が変わったかを確認
ユーザーに「今回の更新は何か（台帳の基準日／届いた資料）」を確認する。基準日（台帳の as-of）と分析日（今日）を押さえる。日付は `YYYYMMDD`。

### 1. 受領ファイルの取り込み
- 新しい基準日の資料は `受領資料_YYYYMMDD/` を新規作成してそこへ**移動**（コピーではない）。
- **資産推移CSVは `00_マスタデータ置き場\32_家計_資産データ\資産推移月次\` に集約**（2026-06-25〜）。投入は `00_マスタデータ置き場` 直下に置いて「整理して」でそこへ振り分く。`create_report.py` がこのフォルダ内の最新CSVを `glob` で自動選択するので、ファイル名を手で直す必要はない。
- **恩株（P3）の更新には SBI証券の保有証券一覧・配当履歴（DISTRIBUTION）** が要る。届いたら `ONK_*` 定数を差し替える（下の対応表）。
- 同種ファイルが複数あれば LastWriteTime が最新を採用。
- 命名はユーザールール（半角英数字・`YYYYMMDD`・スラッシュは `-`）に従う。

### 2. create_report.py の定数を更新
届いた資料に対応する定数を直す（下の「資料 → 定数 対応表」参照）。
**派生値は自動計算なので触らない**（例：`NET_WORTH`・`DEBT_TOTAL`・`RE_LOAN_TOTAL`・`DC_GAIN_NOW`・`RENT_Y`・`ONK_PCT` は他定数から算出）。元の入力定数だけ直せば連動する。

### 3. 手書きの表示文字列を更新（最重要のつづき）
変わった数字が P1 KPI・円グラフ・BS・不動産表・総合評価、P5 強み/弱点/アクションに出ていないか全ページ走査し、該当箇所を直す。比率（自己資本比率・不動産比率・LTV・利回り）も再計算して直す。恩株は `ONK_*` を直せばP3本文（ハイライト等）も定数から描画される。

### 4. 出力ファイル名とCSV読み込み名を更新
- `OUT`（26行目付近）… `資産管理台帳_分析レポート_<分析日YYYYMMDD>_v<N>.pdf`。**上書き禁止**。同日に作り直すなら `v` を上げる。
- CSV読み込みは自動化済み（`資産推移月次\` 内の最新を `glob` で取得）＝**ファイル名の手修正は不要**。
- `c.setTitle(...)` の説明文も内容に合わせて更新。

### 5. 実行
実行すると、PDF生成と**同時に最新PDFが田中亨さんのGmail（ph2144.tt.0609@gmail.com）へ自動添付送信される**。スマホのGmail通知から最新版を開く運用＝Driveの階層を潜らずに済ませるのが目的。送信処理は `create_report.py` 末尾の `send_report_mail()`。**Gmailアプリパスワードはコードに直書きせず、環境変数 `KAKEI_MAIL_PASS` から読む**。

PowerShellツールから実行するときは、`setx` で保存した環境変数が新プロセスに継承されないことがある。**実行直前に User 環境変数から読み込む**こと：
```powershell
$env:KAKEI_MAIL_PASS = [Environment]::GetEnvironmentVariable('KAKEI_MAIL_PASS','User')
$env:PYTHONUTF8=1
python -X utf8 "create_report.py"
```
- `OK: <出力パス>` … PDF生成成功。reportlab 未導入なら `pip install reportlab`。P7の xlsx 読込には `openpyxl` も要る（未導入なら `pip install openpyxl`。無ければP7は注記へ退避）。
- `メール送信完了 → ph2144.tt.0609@gmail.com（...）` … 送信成功。
- `メール送信スキップ：環境変数 KAKEI_MAIL_PASS が未設定です` … 環境変数の読み込み漏れ（PDFは生成済み）。上の読み込み行を付けて再実行する。
- 宛先・送信元はどちらも本人（自分→自分）でGoogle内完結。第三者には渡らない。

（このスクリプトは ASCII の .py なので直接実行してよい。日本語を含む**新規** .ps1 は文字化けするため作らない。アプリパスワードは環境変数に置きコードへ直書きしない＝漏洩防止。）

### 6. 検証（必須）
1. **レイアウト機械チェック**：`verify_report.py` を生成PDFに対して **期待ページ数7** で実行し `LAYOUT OK` を確認（上の「鉄則」のコマンド）。`LAYOUT ISSUES` が出たら座標を動かさず文量で調整して再生成。
2. **目視**：書き出された `*_p1.png`〜`_p7.png` を Read tool で7枚開き、体裁（重なり・はみ出し・余白）を確認。**P3恩株のランキング12行が「ほか9銘柄」行と重ならないか、生涯累計キャプションが年ラベルと衝突しないか**も見る。
3. **数値整合**：総資産＝金融＋不動産、純資産＝総資産−総負債。P1 KPI・BS・不動産表、P2バー、P3恩株（達成度＝配当÷取得額）、P4ローン表、P5リストの数字が互いに一致しているか。

### 7. 後片付けとチェックリスト
- 検証で書き出した `*_p*.png`（中間ファイル）を削除する。
- 直下は**最新レポート1本だけ**に保つ。前の版は `過去レポート/` へ移動。
- `create_report.py` の `checklist` 配列：新たに届いた資料の `pending`（※未取得）フラグを外す。定期資料が増減したら配列も更新。
- 反映した内容が今後の前提になるなら、プロジェクトの CLAUDE.md（注意点）も追記して次回に引き継ぐ。

## 注意点・既知の落とし穴

- **P3恩株は恒久ページ。再生成時に落とさない**（別PCでの改修でP3が抜け「他PCから恩株版が見られない」分岐が起きた履歴あり）。ページ削除・並べ替えの依頼が無い限り7ページ・P3恩株を維持する。
- **DC利回りはユーザー指示で年7%基準**（`DC_RATE`）。変えるなら `DC_RATE` を直し、`dcp/dcp2` の文言と弱点コメントも合わせる。
- **台帳の負債欄は西台と鵜の木のローン残高が取り違えられていた**履歴あり。当初借入額＝評価額の一致（鵜の木2,550万／西台2,250万）で物件を同定すること。台帳側の数字を鵜呑みにしない。
- **西台サブリースは2026年9月が更新期限** → 保証賃料の改定（減額）に注意。
- **医療保険2本（メットライフ・亨/美香）は P6 専用で資産非計上**（掛け捨て・法人負担）。10年払込完了後に名義を法人→個人へ変更する設計＝税務は税理士確認事項。**亨の保険料は暫定値**＝証券・設計書が届いたら `MED_TORU_PREM_Y` と P6 保険一覧を確定値へ。
- CSVは `Import` ではなく Python で `encoding="cp932"`（Shift-JIS）で読む。MF出力はShift-JISが多い。
- **生成直後のPDFは Google Drive 同期にロックされ、削除・上書きできないことがある**。少し待つか `v` を上げる。
- **個人の金融情報を含む。内容を外部サービス（Web検索・外部API等）へ送信しない。** 中間ファイルは作業後に削除。
- フォントは `C:\Windows\Fonts\meiryo.ttc` / `meiryob.ttc` を直接登録（Windows前提）。
- **前月比サマリーはCSVから自動計算**。`CUR_M`/`PREV_M`/`FIN_DIFF`/`TOT_DIFF` を最新月 vs 前月で算出。

## 付属ツール・参照
- `verify_report.py`（このスキルフォルダ内・ASCII製で直接実行可）… レイアウト検証ツール。ページ数・マージン越え・下端あふれを機械チェックし、各ページPNGを書き出す。要 `pymupdf`（未導入なら `pip install pymupdf`）。**必ず期待ページ数7で**かける。
- `send_reminder.py`（94直下）… 次回更新に必要なデータ（`checklist` と一致）を頻度別にまとめ、本人Gmailへ催促メールを送る。「必要データを催促して」で実行。`$env:KAKEI_MAIL_PASS = [Environment]::GetEnvironmentVariable('KAKEI_MAIL_PASS','User')` を読み込んでから `python -X utf8 send_reminder.py`。checklist を増減したら create_report.py と send_reminder.py の両方をそろえる。
- 数値の出所・確定経緯・各資料の詳細は **プロジェクトの CLAUDE.md（94_家計管理）** が一次情報。迷ったらそちらを正とする。
